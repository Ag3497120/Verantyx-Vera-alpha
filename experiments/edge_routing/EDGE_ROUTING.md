# 面→辺の完成形 — 辺は節点の経路語彙を24語の外へ広げるか

事前登録 2026-08-19。実行前に書き、実行後に数字だけを埋める。

## 出発点(記録済みの事実、hierarchy.py の docstring に固定済み)

- 節点の経路語彙は面に載った語が全て: 面上 20/24、面外 0/60。
- 面を増やすと壊れる: 腕あたり4/8/16/32/60個 → 正答 4/3/1/0/0。
- よって CAPACITY = 6腕×4面 = 24語、超えたら層を足すしかない。

一方、辺(コーパスが実際に書いた共起対、vera_edges.db 199万対)は
面の枠を取り合わない — 核ごとの関係集合として照合時に引ける。
辺はコーパス由来なので「配置は情報を増やせない」に抵触しない。
生成側への辺供給は配線済み(4974f55)。残るは経路選択そのもの。

## 設計

実連合(ja 89,369核)+実辺で、単一節点の経路選択を測る。木全体の降下
ではなく**節点の語彙**の測定 — 天井の主張がそこにあるため。

- 腕6本 = 実在の核6つ(質量順・facet30以上・辺10以上、決定論的に選抜)。
- 面 = 各核の top-4 facet(frequency、build_shell_from_store と同じ)。
- 探針 = 6核のうち**ちょうど1核だけ**が facet として持つ語(鍵が決定
  可能な語のみ)。面上と面外に分ける。核あたり面外は40語まで。
- 経路A(面のみ): 語を面に持つ腕へ。無ければ no_route。
- 経路B(面∪辺): 語を 面∪辺端点 に持つ腕へ。**2腕以上が名乗れば棄権**
  (同点は棄権 — concord で2回測って確定した規律)。
- 指標: 正答 / 誤答 / no_route / 棄権、面上・面外別。

## 事前予測

- H7: 面外の回復 — Aは構造的に0。Bは正の回復を出し、誤答は正答より
  少ない(辺は核固有の実測関係なので、他腕へ流れる前に棄権が立つはず)。
- H8: 面上はA・Bで変わらない(辺は加算のみ、面の一致を奪わない)。
- リスク(正直に): 辺端点は 使用・他人 のような一般語を多く含む。
  一般語は複数腕の辺に現れ、棄権が増える。回復率がどこまで棄権に
  食われるかが本測定の答え。

## 停止条件

面外で B の誤答 > 正答 なら、節点レベルの辺経路は否定と記録して止める。

## 結果(2026-08-19、実連合89,369核+実辺、results_edge_routing.json)

腕の選抜は2回衛生を直した(生の質量順が 二・三・displaystyle という
ジャンクハブ→is_junk_core+語彙で除外→Wiki定型見出しが残る)。回復率は
選抜に関わらず安定していたため、質量順スライスと法律テーマスライス
(罪/法/権で終わる核)の両方を並記する。判定規則は同一。

```
                       面上(A=B)     面外: A     面外: B(面∪辺)
slice_mass  (187語)     7/7 正       0        正43 誤0 無144 棄0
slice_legal (240語)     2/2 正       0        正16 誤0 無224 棄0
```

- **H7 確認**: 面外の回復は正(23% / 6.7%)、誤答は両スライスとも **0**、
  棄権も 0。面のみでは構造的に 0 だった語が、辺で正しい腕に届く。
- **H8 確認**: 面上は A・B で完全一致(辺は加算のみ、面の一致を奪わない)。
- 停止条件は非発動。

## 留保(正直に)

回復が部分的(6.7〜23%)なのは、**出荷済み辺サイドカーが核あたり top-8
辺で切られている**(release.py export_edges top=8)ため — 端点は核あたり
高々十数語しか無い。これは思想の天井ではなく書き出しの天井。辺を
増やした再書き出しで回復率がどこまで伸びるか(そして誤答0が保たれるか)
が次の測定。
