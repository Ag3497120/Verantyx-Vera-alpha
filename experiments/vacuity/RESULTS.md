# 実測結果: 空虚な証明の番犬 — 二度の強化で働くようになった

事前登録: PREREG.md / 生データ: results.json

## 動機
今日、駆動層が**予算切れ同士を「一致」と読み**、真の命題を空虚に
「証明」した。報告した 8/8 は偽で、本当は 5/8 だった。
**Lean は捕まえられない** — 独立検査は主張の真偽を見るのであって、
導出の本物さは見ない。

単発の修理は済んだ。だが同じ**形**の穴は他にもあり得る:
**規則集合が壊れて何でも等しくなる**場合である。各証明は個別には
整合しているので、内部からは気づけない。

## 番犬: 偽の等式が証明できないこと
規則を増やすたびに、偽と分かっている等式が依然として証明**できない**
ことを確かめる。鳴いたら、その時点以降の全ての「証明」は無価値。

## 番犬自身を二度作り直した(ここが本題)
| 版 | 偽の等式 | `add(?x,?y)→0` を捕らえるか |
|---|---|---|
| 1 | 構成子のみ(`0 = s(0)` 等) | **見逃す** |
| 2 | +閉じた項で演算子を通る(`add(s(0),0) = 0` 等) | **まだ見逃す** |
| 3 | **+変数を含む**(`add(x,y) = 0` 等) | **捕らえる** |

見逃した理由が構造的である:
- 版1は演算子に触れていないので、演算子を潰す壊れ方に届かない
- 版2は閉じた項なので、**正しい規則が先に発火して壊れた規則が影に隠れる**
  (`add(s(0),0)` は `add(?x,0)→?x` が先に噛み、`add(?x,?y)→0` は出番が無い)
- 壊れた規則が表に出るのは**変数を含む項**だけ

**番犬は、壊れ方が実際に噛む形の項を持たねばならない。**

## 最終の結果
    正常系(定義のみ → G1〜G8 を1本ずつ昇格、全9段)
        番犬は**全段で静か**(吠え 0)。8/8 の証明は空虚ではない。

    故意に壊した系
        add(?x,?y) → 0   → 2件を捕らえる(add(x,y)=0, mul(x,y)=0)
        mul(?x,?y) → 0   → 1件を捕らえる(mul(x,y)=0)
        s(?x) → 0(崩壊) → 13件を捕らえる

## 残る限界(正直に)
- 番犬は**偽の等式の一覧**であって、完全性の保証ではない。列挙していない
  壊れ方は依然として見逃す。今日3回とも「見逃す→強化」で見つけており、
  **次の壊れ方も同じ経路でしか見つからない**可能性が高い。
- 「証明できないこと」の確認は、探索の予算内での話である。予算を増やせば
  証明できてしまう偽があれば、それは見逃す。
