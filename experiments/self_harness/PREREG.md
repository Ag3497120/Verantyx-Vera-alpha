# 事前登録: 自分のハーネスを自分で測る — 作業ログ→変分→台帳

日付: 2026-08-21。**この文書を書き終えてから測定を走らせる。**

## なぜ証明器を対象にするか(構想の完結点)

構想は「行動の蓄積で覚えて発明する」。それには**実在の行動ログ**と
**安い審判**の両方が要る。LLM の作業ログは審判が高く騒がしい。
一方 **証明器自身の作業ログ**は:

- 実在する(構成した治具ではない — proof_ledger の how / trials)
- 審判が無料で決定的(Lean + 目標集合)
- 変えられる把手が本物(波の幅・深さ・予算・手渡し在庫・エネルギー)

つまり Vera が**自分のハーネスを自分で測る**。procedure_vary の規律
(単一変更のみ — 二つ変えて失敗したら原因が名指せない)をそのまま使う。

## 実装

1. `verantyx/self_harness.py`
   - `lift(how)` — 証明器の作業ログ(`how` 文字列)を**ハーネス項**へ:
     "direct" → hact(0) / "induction on x" → hseq(hact(1), hact(2))
     "+ L10"(発明補題を使用)→ 末尾に hact(3) / "+cond" → hact(4)
     写像は閉じた表。読めない how は **未写像**として数える(推測しない)
   - `knobs()` — 実在の把手(wave / max_depth / invention_budget /
     手渡し在庫の有無 / エネルギーの有無)
   - `variations()` — 親から**単一変更**の変分だけを列挙
2. 審判 = 目標集合(確認13の48目標)。成功 = 証明数、害 = 証明数の減少。

## 測定(完了基準5点)

- Q1 正: 作業ログがハーネス項に写る(48目標のうち写った数と未写像数を
  報告。未写像は推測しない)
- Q2 反証: **害の変分**(wave=1 に絞る等)が証明数の減少として検出される
- Q3 拒否: 差が ±1 以内の変分は**棄権**(ノイズから勝者を選ばない)。
  採択線は **+2目標以上**(ハーネス実験と同じ線)
- Q4 順序: 目標の実行順を反転しても採否が一致
- Q5 独立: 採択された変分でも **Lean 検査が全通・不健全0**
  (速くなっても健全性が落ちたら失格)
- 台帳: 全変分を `harness_facts.json` と同じ形で、条件(目標集合の版・
  親の設定)つきで記録。文脈鍵は `prover@battery`

## 採択基準

- R1: Q1〜Q5 を全て満たす
- R2: 採択・棄権・害のいずれかに**全変分が分類される**(黙った採択0)
- R3: 採択された変分があれば、その事実が台帳に証人つきで載る
  (無ければ「この把手では改善が見つからなかった」を記録 — 失格ではない)

## 停止条件

Q5違反(不健全が出た)→ 即棄却。速さのための変更が健全性を削ったら、
それは改善ではない。
