# 事前登録: 辞書辺(定義文の反復共起×共有区切り)で同義語の壁を渡す

日付: 2026-08-19 / 実測前に登録 / 発案は操作者
「言葉の区切りをたくさん分けて関連を接続するのを繰り返す。配布前に言葉を
固めるデータの多量投入が要る。ただ投入するだけではいけない」

## 実測済みの壁
Appleメモ128本への「veraの改善点/欠点」が明記なし — メモは弱点/劣る点と
書く。類縁格子の意味は4%天井。jgen辞書実験: 順位づけ可・主張(極性)不可
(54.8%)。→ 大量データは経路にだけ入れ、票と本文には入れない。

## 収穫規則(閉じた二重ライセンス)
jawiki_defs.json(1,419,406定義)から、同一文に共起した内容連の対のうち:
  1. 区切りの共有: 2語が漢字1字以上を共有する(欠点/弱点の「点」、
     長所/短所の「所」) — 操作者の「区切りを分けて接続」の実装
  2. 反復: 異なる定義文で2回以上共起(1回きりの共起は事故)
  3. 語形: 各2〜6字、Template/ASCII混じり文は捨てる
出力は build/def_edges.json(語→隣語、上位32まで)。

## 配線(置換は必ず名乗る)
文書 lookup の「明記なし」直前でだけ発火: 不在の主題語 P の辞書隣語 P'
が文書に実在すれば、その行を引用し、reached_via「P→辞書辺→P'」と
note で置換を名乗る。verdict は DOCUMENT_LINE のまま(引用は逐語)。
主題取りこぼし門(賢者の石)より後、つまり主題そのものが不在と確定した
後にだけ動く。
