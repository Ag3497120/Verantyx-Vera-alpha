`theorem t (a b c : Int) : 原式 = 簡約 := by omega` は**全ての整数に
ついて**の主張である。つまりカーネルは変数を含む項を書き換えることで、

## B群: 帰納法を要する命題(10本)
    ①が導出           **4/10**
    Lean が omega で通した  6/10
    素朴な induction 戦術で追加に通ったもの  0

**「導出できた」4本の中身を確かめたところ、4本とも規則そのものだった**:
    右単位元 n+0=n   → 規則 add_zero_r
    左単位元 0+n=n   → 規則 add_zero_l
    乗法単位元 n*1=n → 規則 mul_one_r
    乗法零元 n*0=0   → 規則 mul_zero_r
カーネルはこれらを**証明していない。公理として持っている**。
規則 `?a + 0 → ?a` は定理 `n+0=n` そのものである。

**真に帰納法を要する5本(加法可換・乗法可換・分配・右分配・乗法結合)は、
一本も導出できなかった。** 事前登録の予測(0本)は実質的に正しかった。

## 測定を一度誤り、それが実際の欠陥を暴いた
初回は「導出 5本」と出て、加法の**結合律**が導出されたように見えた。
原因は私の比較方法で、`simplify` が返す `term` は**文字列**であり、
`term_to_str` が右側の複合項の括弧を落としていた:

    a + (b + c)  → 印字 "a + b + c" → 読み直すと (a + b) + c   ← 別の項

往復は 2/8 で破綻していた。Int では両方とも真の等式になるので実害は
出ていなかったが、**印字は項の表現であって「たまたま同値な別の項」では
ない**。非結合的な演算子を載せた瞬間に嘘になる。

修理(右側の複合項には常に括弧)+ fork 162本目 `REWRITE_PRINT_ROUNDTRIP`。
実験も項どうしの比較に直し、B群は 5→**4** になった。

## 壁の正体
壁は「帰納法という規則が足りない」ではない。**カーネルは項を書き換える。
証明は目標を操作する。** 帰納法は `∀n, P n` を `P 0` と
`P k → P (k+1)` という**部分目標に割る**規則であり、カーネルには
「目標」という概念が無い。項をいくら書き換えても部分目標は生まれない。

規則集合を増やしても越えられない。越えるには**証明状態(目標の木)を
持つ層**が要る — それは書き換えカーネルではなく、証明器である。
