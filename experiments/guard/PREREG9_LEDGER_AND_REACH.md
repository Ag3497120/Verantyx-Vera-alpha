# 事前登録9: 台帳の有界化(L)と、IDE から全機能に届くこと(E)

日付: 2026-08-22。**この文書を確定してから作る。**

## L 台帳の有界化 — 実測した問題

`guard check` は毎ターン台帳を丸ごと書き戻す。実測:

| 約束 | 1照合 | 保存 | 台帳 |
|---|---|---|---|
| 20 | 0.02ms | 0.09ms | 3KB |
| 1,000 | 2.48ms | 1.08ms | 164KB |
| 5,000 | 12.9ms | — | — |

速度は当面問題ない。問題は**上限が無い**こと。段4以降、読めた指示は
全部候補として席に着くので、月単位で使えば候補は数千になりうる。

### 線: 消さない。**書庫へ移す**

台帳の精神(退役は追記、履歴は provenance)を破らない。よって:

L1. **履歴は末尾 max_history 件だけ生かし、落とした分は合計に畳む**
    (checked/kept の総数は保存 — 数が消えない)
L2. **生きた台帳の上限を超えたら、候補を書庫(append-only の jsonl)へ
    移す**。移すのは **①退役済み ②一度も発火していない候補** の順。
    書庫を読めば必ず見つかる(消滅しない)
L3. **人が採用した約束(adopted)は決して移さない** — 利用者の言葉は
    こちらの都合で棚から降ろさない
L4. 間引きのあと、照合と保存が上限内に収まる

## E IDE から全機能に届くこと

IDE は MCP 経由なので、**CLI にしか無い機能は IDE から使えない**。
棚卸し(実測): CLI 35コマンド / MCP 127扉。名前一致で扉の無い CLI は18。
そのうち **導入・対話・LLM 系は扉にしない**(mcp / mcp-config / setup /
wizard / review-ai-facts / push-store / agent — サーバの中からサーバを
起動する等、意味を成さないか IDE 側に既にあるもの)。

**扉にするのは、機能が本当に届いていない5つ**:
`doctor`(二つの顔+配線の健康)/ `simplify`(項の書き換え)/
`lexicon`(静的辞書)/ `self_audit`(文書の欠け監査)/
`pour_text`(手元のテキストを店へ、**上限つき**)。

## 測定(V39〜V44)

- V39 履歴の間引きで**総数が保存される**(checked/kept の合計が一致)
- V40 生きた台帳が上限内に収まり、**移したものが書庫で全部見つかる**
- V41 adopted は1本も移らない
- V42 間引き後の照合が 5ms 以内、保存が 5ms 以内(1,000候補の投入後)
- V43 新しい5扉が MCP から呼べて、扉数が CLI 側から見た数と一致する
- V44 `pour_text` は上限を超えて取り込まない(暴走しない)

## 停止条件

- 書庫に無いものが消えたら間引きごと棄却(消滅は台帳の死)
- adopted が1本でも移ったら棄却
