# 事前登録6: 単体 Vera — 決定論的に聞ける装置としての保証

日付: 2026-08-22。提出まで10日。**この文書を確定してから作る。**
PREREG5(凍結)の続き。前提: 番人(フック)側の保証 G1〜G4 は測定済み。

## なぜ要るのか

提出物には二つの顔がある。**①フックとして働く番人**と、**②単体で
知識を入れて聞ける装置**(数学・企業文書・連邦を含む)。②の入口は
既にある(`pour` / `remember` / `ask` / `math` / `code` / `field`)が、
**他人のマシンでその性質が今この場で成り立つことを示す手段が無い**。
番人に対して doctor を作ったのと同じものを、単体側にも作る。

新機能は足さない。既にある `document_ingest` と `consensus_over_store`
を、**測るためだけに**通す。

## 保証する4つ(S1〜S4)

S1. **在庫にあることは答える** — 取り込んだ文書にある事柄は
    `ANSWER` と核を返す
S2. **無いことは型つきで断る** — 店に無い問いは `UNKNOWN_*` と理由を
    返す。空の答えや、それらしい近傍を返さない(**捏造ゼロ**)
S3. **取り込み順に依らない** — 文書を入れる順を変えても、同じ問いに
    同じ判定と同じ核を返す
S4. **答えは店にある語だけでできている** — 返した本文の語が全て店の中に
    ある。店の外の語を1語も持ち込まない

S2 と S4 が、埋め込み検索+LLM の RAG が構造上できない主張。近傍は
常に何かを返し、生成は店の外の語を混ぜる。

## 測定(V28〜V30)

- V28 S1〜S4 が小さな治具(企業文書2件+技術方針1件)で成立する。
  質問は在庫内3問・在庫外3問。**在庫外で ANSWER が1件でも出たら
  その場で不合格**
- V29 **壊した装置で BROKEN を返す**(番人の V25 と同じ規律 —
  通るだけの自己検査は自己申告)。3種を注入して名指しできること:
  ①何にも答えない ②在庫外に答える(捏造する)③取り込み順で答えが変わる
- V30 `vera doctor` が二つの顔(番人 G1〜G4 と単体 S1〜S4)を1回で
  検査し、片方が壊れていればもう片方が緑でも BROKEN、終了コード1

## 保証しない(名指しして直さない)

- 質問文の自然言語解析(問いの言い換え・複文)。単体側も**語**で聞く
- 数学・連邦・企業文書の各機能の正しさ(それぞれ別の測定が既にある)。
  doctor が見るのは**この4つの性質だけ**
- 検索の網羅性(在庫にあるのに見つからない場合がありうる)。S1 は
  治具の範囲で成立することしか主張しない

## 停止条件

- 壊した装置で OK を返したら doctor ごと棄却
- doctor が5秒を超えたら治具を小さくする(導入直後に叩くもの)
