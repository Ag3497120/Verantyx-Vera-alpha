## ⑦ 仮説の判定

> H: 「言葉の理解を強化する」= その分野のコーパスを店に入れること

**半分当たり、半分外れ。**

**当たった側**: 語の**在庫**はコーパスでしか増えない。本店では
pytest/eslint/docstring/絵文字/テストが 0 core で、`siblings` は空を返す
以外に何もできなかった。490 万字入れて 20/24 が入り、
typescript→javascript が**実際に回復した**。ここは間違いなく
「モデルを賢くする」話ではなく「何が書いてあるか」の話だった。

**外れた側**: 在庫が増えることと、**幾何が使える形になること**は別だった。

1. **量では買えない**。回復したのは、同じ**行**に選択肢として並んでいた
   1 対だけ(6 行)。`pytest`/`unittest` は共起 0 行で、25 core あっても
   何も出ない
2. **頻度は普通語と内容語を分けない**。`is`(0.1641%)が `pytest`(0.1709%)と
   同じ帯にいる以上、share 閾値でこの仕事はできない。安全な 2% は 3/26 しか
   落とさず、有効な 0.02% は番人の語を 7 語とも殺す
3. **自分について書いた文章はコーパスとして効きが悪い**。62.4% が自己記述
   だったため、`pytest` の姉妹語は `echo`・`証人`(自分の PREREG の語)に
   なった。**必要なのは「Vera が pytest について書いた文」ではなく
   「pytest と unittest が選択肢として並んだ文」**

## ⑧ コーパスでは直らないもの(名指し)

事前登録で先に 4 つ挙げ、測定で 2 つ増えた。

**事前に挙げ、実測でも動かなかったもの**

1. **分節器の語パターン** — `console.log` は `[A-Za-z0-9']+` により
   console と log に割れる。実測: 指示文 `Do not use console.log` の
   forbids は **`console`** であって `console.log` ではない。
   コーパスを増やしても割れ方は変わらない
2. **極性(禁止か要求か)** — 既測 54.8%。今回何も測り足していないので
   **変わったとは言わない**。語彙が答えるのは「どの語か」だけ
3. **抽出の被覆** — ⑥ で実測。8/20 が前後で完全一致。
   `TypeScriptを使ってください` が読めないのは規則の問題で、店の問題ではない
4. **証人の照合** — INVOKED / MENTIONED はシェルの語り分けで店を読まない。
   `run_confirm3.py` は新店の有無に関係なく 5/5

**測って新たに分かった、コーパスでは直らないもの**

5. **share 閾値による「約束の語にしてよいか」の判定** — ③ の算術。
   これは「もっと良いコーパス」で直る種類の問題ではない。普通語と道具名は
   出現頻度の分布が**重なる**もので、分けたいなら頻度**以外**の軸が要る
6. **書かれていない対比は出ない** — `unittest` はコーパス全体で 0 core。
   `siblings` は共起の幾何なので、共起していないものを推論する力は無い。
   **「誰も書かなかった禁止」を捕まえられるのは、「誰かがその二つを
   並べて書いた」場合に限られる**

**逆に、コーパスで直りそうだと実測が示したもの(未検証・提案)**

- typescript/javascript が 6 行の共起で回復したことは、
  **「対比が並ぶ文」を少量だけ入れれば効く**可能性を示す。ただしこれは
  本実験が測ったことではない。**測っていないので、効くとは書かない**
