# 事前登録: 分野コーパスを入れると番人の語彙は変わるか

日付: 2026-08-21。**この文書を確定してから測定する。**
前段: experiments/guard/PREREG{,2,3}.md、RESULTS3 の「残る限界」の第1項。

## 仮説(検証するもの)

RESULTS3 はこう名指した:

> **日本語の一般語の required は執行できない**。「必ずテストを実行して」は
> requires=[テスト] になるが、テストという名の道具は無い(pytest が走っても
> 一致しない)。店の姉妹語で テスト↔pytest を橋渡しする案はあるが、過剰主張の
> 危険があるので事前登録してから

仮説 **H**: 「Vera の言葉の理解を強化する」とは、モデルを賢くすることではなく
**その分野のコーパスを店に入れること**である。

本店 `vera_store.json` は `hf:imdb` — 英語の映画・人物・地理の散文。番人が
扱う語の被覆は既報でゼロ。ここでは**別ファイルの店**に技術文書だけを入れ、
何がどれだけ変わるかを測る。**本店は絶対に上書きしない。**

## 入れるコーパス(測定前に確定・corpus_manifest.json)

`collect_corpus.py` が集めた md のみ。実測値:

- **549 ファイル / 4,935,397 文字**(en 376 / ja 169 / zh 4)
- 除外: 秘密らしい字面 **34 ファイル**(鍵・トークン・メールアドレス)、
  内容重複 **94**、200 文字未満または読めない **2**
- **既知の偏り**: `verantyx-cli/docs/chronicles/Vol3_…md` 1 ファイルだけで
  1,313,904 文字 = 全体の 26.6%。Vol1/2/4 と合わせて日本語開発誌が
  1,940,000 文字。**均さない**(切り詰めは恣意的な介入なので、偏りは
  事実として報告する側に倒す)

## 取り込みの経路(発明しない)

`verantyx.document_ingest.ingest_documents` / `Document` をそのまま使う。
1 ファイル = 1 Document、source は絶対パス。保存先は
`experiments/guard/corpus/guard_store.json`。

## 測定 C1〜C5(基準はここで固定)

### C1 被覆 — 番人の語彙が新しい店に入るか

閉じた 24 語(**今ここで固定**、測定後に足さない)。店は casefold するので
比較は全て小文字。

- ja(8): 絵文字, テスト, 型注釈, 敬語, 箇条書き, 見出し, 注釈, 検証
- en/code(16): typescript, javascript, pytest, unittest, eslint, prettier,
  mypy, ruff, black, print, console, todo, emoji, docstring, lint, commit

各語について「facet として何個の core に載っているか」「core 自身として
存在するか」を、**本店と新店の両方**で数えて対比表にする。

**既知の分節の性質(先に書いておく)**: en の語パターンは `[A-Za-z0-9']+`
なので `console.log` は決して 1 facet にならない(console と log に割れる)。
`print文` も同様に割れる。だから 24 語の側を `console` にしてある。
これはコーパスでは直らない — **分節器の性質**であって語彙の不足ではない。

**判定**: 24 語のうち facet として存在するものが
- **18 以上** → 被覆は改善した
- 4〜17 → 部分的
- **3 以下** → 改善しなかった(H はこの面で外れ)

### C2 語の質 — 約束の語にしてよい語と、してはいけない語が頻度で分かれるか

新店の全 facet について share = (その語を facet に持つ core 数)/(全 core 数)
を出し、順位と割合を報告する。閾値の候補は **2%, 1%, 0.5%, 0.2%** の 4 本
(本店の既存ハブ閾値 2% を含む)。それぞれで:

- **落とすべき普通語**(en: the, is, are, new, use, used, using, one, time,
  part, name, make, get, set, run, file, code, all, can, will /
  ja: 場合, 必要, 使用, 以下, 内容, 方法)= **26 語**のうち何語落ちるか
- **落としてはいけない内容語**(typescript, javascript, pytest, unittest,
  eslint, prettier, mypy, ruff, docstring, emoji, 絵文字, 型注釈, 敬語,
  箇条書き)= **14 語**のうち何語**誤って**落ちるか

**判定**: 普通語 26 語の **80% 以上(21 語以上)を落とし、内容語 14 語を
1 語も落とさない**閾値が 4 本の候補の中に **1 本でもあれば「分かれる」**。
無ければ「**分かれない**」と書き、誤って落ちる内容語を全部名指しする。

### C3 姉妹語 — 書かれていない禁止を回復できるか

`verantyx.covenant.siblings(store, term, limit=6)` を新店で、既定の
パラメータ(min_shared=2, max_fanout=60, max_common=0.02)のまま呼ぶ。

対象 6 語と、**期待する代替**(測定前に固定):

| 語 | 期待する姉妹語(いずれか1つ以上が上位6件に入れば成功) |
|---|---|
| typescript | javascript |
| pytest | unittest / nose / test |
| print | log / logging / console |
| eslint | prettier / ruff / lint |
| テスト | pytest / unittest / test |
| 絵文字 | emoji / 記号 / 顔文字 |

**判定**: 6 語中 **3 語以上**成功 → 姉妹語は回復する。
1〜2 → 部分的。**0 → 回復しない**(できたことにしない)。
成功不成功にかかわらず**上位6件を全て記録**する。

### C4 非干渉 — 新しい店を作っても既存の緑は緑のまま

新店を作る**前と後の両方**で走らせ、同じであることを確かめる:

- `verantyx.cross_geometry_forks.all_cross_geometry_forks()` = **88/88**
- `experiments/guard/run_confirm.py` = **7/7**
- `experiments/guard/run_confirm2.py` = **5/5**
- `experiments/guard/run_confirm3.py` = **5/5**
- `experiments/guard/run_confirm_lang.py` = **3/3**
- `vera_store.json` の (size, mtime, 先頭64バイトの sha256) が不変

**判定**: 全て一致 → 非干渉。1 つでも崩れたら **C1〜C3 の解釈を止めて
崩れだけを報告する**(壊した状態で出た数字は数字ではない)。

### C5 抽出は変わらないはず — 変わらないなら「変わらない」と書く

20 本の指示文に `extract_covenants` をかけ、候補が出た本数を数える。
抽出は閉じた正規表現なので、**コーパス投入で変わらないと予想する**。

**判定**: 投入前後で同一 → 「コーパスは抽出に効かない」と記録する。
もし変わったら、それは抽出が店を読んでいるという意味なので、**その事実を
先に報告する**(効いた、と喜ばない)。

## 停止条件

- **S1** 取り込みで `sentences` が **5,000 未満** → 4,935,397 文字が店に
  届いていない。C1〜C3 を測らず、取り込み経路の欠落として報告する
- **S2** 新店の core 数が **1,000 未満** → `siblings` の `max_common` は
  core 200 未満で無効化される設計で、1,000 未満では share 閾値の議論が
  成り立たない。C2/C3 を測らず報告する
- **S3** C4 が 1 つでも崩れる → 全解釈を止める(上記)
- **S4** `vera_store.json` の指紋が変わる → **即時中止**。他は何も報告しない

## 予想を書かない線

C1〜C5 の数値は全て実行結果のみを書く。ここに書いてよいのは**基準**だけで、
「たぶんこうなる」は書かない。仮説 H が外れたらそのまま記録する。

## 先に名指ししておく「コーパスでは直らないもの」

測定後に言い訳にしないため、**構造上コーパスで動かない**と分かっているものを
先に書く。測定はこれを覆すかどうかも見る:

1. **分節器の語パターン** — `console.log` / `print文` が 1 語にならないのは
   `[A-Za-z0-9']+` の性質。コーパスを増やしても割れ方は変わらない
2. **極性(禁止か要求か)** — 既測 54.8%(コイン投げ)。語彙が答えられるのは
   「どの語か」だけで、「してよいか」ではない
3. **抽出の被覆** — `extract_covenants` は閉じた表と正規表現(C5 で確認)
4. **証人の照合** — INVOKED/MENTIONED はシェルの語り分けで、店を読まない
