# 事前登録7: IDE から CLI へ — 文書・分野・扉・設定

日付: 2026-08-22。**この文書を確定してから測る。** 提出まで日数が
限られており、機能追加ではなく**入口の移設**だけを行う。

## 何が無かったか(棚卸しの実測)

CLI: pour / remember / ask / code ingest / field ほか。
MCP: 126扉(`load_documents`・`ingest_documents`・`vera_domain(s)`・
分野モジュールの提案/承認 を含む)。
**文書投入と分野管理は MCP にしか無く、CLI から届かなかった。**
Swift IDE の MCP 画面がしていたのは ①他サーバの接続管理
②設定スニペットの発行。①は Claude Code 自身の機能なので写さない
(同じ仕事を二つ持つと必ずずれる)。②は CLI に無かった。

## 移設の設計(扉は一つ、入口は二つ)

扉ごとに CLI のコマンドを書き写さない。`mcp_server.serve` から
`build`(走らせずに扉を返す)を切り出し、CLI はその扉を呼ぶ。
薄い包みは、名指しされた2つ(文書・分野)だけ置く。

## 保証(P1〜P4)

P1. 文書が CLI から入り、入れたものが聞ける(**IDE と同じ扉**を通る)
P2. 分野の一覧・登録が CLI から届く
P3. **126扉すべてが CLI から呼べる** — CLI が見る扉の数が MCP の
    扉の数と一致し、無い扉は型つきで断る(推測して近いものを実行しない)
P4. `mcp-config` は既定で**何も書かない**。`--install` のときだけ書き、
    **他サーバの設定を壊さない**(vera-memory の項だけ差し替える)

## 測定(V31〜V34)

- V31 一時の店に CLI で文書を入れ、`ask` が ANSWER と正しい核を返す。
  入れていない問いは UNKNOWN のまま(捏造ゼロ)
- V32 `domain list` が扉の答えを返す
- V33 CLI の扉数 == MCP の扉数。存在しない扉は `UNKNOWN_NO_SUCH_DOOR`
  で、**終了コードが 0 でない**
- V34 `mcp-config` 既定で設定ファイルが作られない。`--install` 後、
  既存の別サーバ項が残り、vera-memory の項だけが入る

## 停止条件

- CLI と MCP で扉の数が違ったら橋を棄却(表面がずれた時点で意味がない)
- `--install` が既存の設定を壊したら install ごと棄却(既定は表示のみに)
