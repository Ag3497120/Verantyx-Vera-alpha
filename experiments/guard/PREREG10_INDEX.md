# 事前登録10: 能力の索引 — 「それは既に在るか」に1コマンドで答える

日付: 2026-08-22。**この文書を確定してから作る。**

## なぜ要るのか(実測した規模)

モジュール 187ファイル / **67,145行**、MCP扉 **129**、fork **89**、
事前登録 **74通**、結果文書 **37通**、これまで.pdf **441ページ**。

この量は人の作業記憶にも、モデルの文脈窓にも入らない。だから作業者が
毎回**既にあるものを作り直す**。実際この会話で2度起きた(①保留の窓を
作りかけて、22の承認扉と7の欠け扉が既にあると分かった ②「意味の
一般化はできない」と断言したが、PDFに**できている実測**があった)。

これは注意力の問題ではなく**索引の不在**なので、注意しても再発する。

## 線: 索引は**生成物**であって一覧ではない

手書きの一覧は書いた瞬間から古くなり、地図自体が同じ問題を起こす。
よって索引は毎回**コードと文書から導出**する。索引が実物とずれることは
構成上あり得ない、を性質として固定する。

## 保証(I1〜I4)

I1. **導出**: 扉・fork・CLI命令・モジュール・事前登録/結果を、
    ソースと文書から**その場で**読み出す(手書きの表を持たない)
I2. **一致**: 索引が数える扉数・fork数が、実物の数と一致する
I3. **検索**: 語で引くと、実在する資産だけが返る。順位は決定的
    (埋め込みを使わない — この装置の線)
I4. **拒否**: 無いものは `UNKNOWN_NOT_FOUND`。似た名前を代わりに
    返さない(推測は再実装より悪い — 在ると誤認させる)

## 測定(V45〜V48)

- V45 I2: 索引の扉数 == mcp_server の実数、fork数 == 登録簿の実数、
  事前登録の通数 == ファイル数
- V46 I3: 「文書 投入」「約束 破棄」「配置」で、実在する扉・実験が
  上位に出る(名指しで確認)
- V47 I4: この資産群に存在しない語で `UNKNOWN_NOT_FOUND`。
  **試す語をこの文書に書かない** — 書けば索引がこの文書に当たって
  しまい、自分の仕様書で自分を汚す(測定は run_confirm10 側で持つ)
- V48 I1: 索引に**手書きの資産名が埋め込まれていない**(ソースから
  導出していることを、扉を1本増やした状態で数が動くことで確かめる)

## 停止条件

- 索引の構築が5秒を超えたら簡略化する(実装前に毎回引くものなので)
- 無いものに何かを返したら索引ごと棄却
