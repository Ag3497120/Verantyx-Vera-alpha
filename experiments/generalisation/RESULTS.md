# 実測結果: 汎化 — 手で与えれば通る。自動化はまだ届かない

事前登録: PREREG.md / 生データ: results.json

## 題材(古典例)
    rev(nil)=nil / rev(cons(h,t))=app(rev(t),cons(h,nil))
    revacc(nil,a)=a / revacc(cons(h,t),a)=revacc(t,cons(h,a))

    T   rev(l) = revacc(l, nil)          ← 帰納が通らない
    T'  app(rev(l), a) = revacc(l, a)    ← 汎化した形(T は a:=nil の特別な場合)

## 結果
| 命題 | 駆動層 | Lean |
|---|---|---|
| T | **証明できず**(正直に詰まる) | VERIFIED(真) |
| **T'** | **証明した** | VERIFIED(真) |
| 自動汎化の候補 | **証明できず** | — |

T の段(詰まった箇所):
    app(revacc(t, nil), cons(h, nil))  vs  revacc(t, cons(h, nil))
T' の段(閉じた):
    revacc(t, cons(h, a))  =  revacc(t, cons(h, a))

## 途中で見つけた2件

### ① 二段階正規化が要る(汎化とは別の問題だった)
最初は **T' も落ちた**。原因は汎化ではなく**仮定の適用時期**:
IH `app(rev(?t), ?a) → revacc(?t, ?a)` を最初から混ぜると、
leftmost-innermost が内側で早く発火し、定義による整形(結合律)を妨げる。

    IHを最初から混ぜる → 左 app(revacc(t, cons(h,nil)), a)   一致せず
    **二段階**(①定義だけで正規化 →②その後にIH)
                      → 左 revacc(t, cons(h, a))            **一致**

探索ではなく、段の**固定された順序**である。正しい汎化を与えても、
適用順が悪ければ閉じない — **汎化の失敗と戦略の失敗は別**。

### ② ハーネスの置換バグ(自己修正)
`revacc(l, nil)` に素の `str.replace("l", "nil")` を当てて `ninil` を
作っていた。語境界つきの置換に修理。初回の T の基底 `nil` vs `ninil` は
この産物で、命題の性質ではなかった。

## 自動汎化は届かなかった — そして**それでよかった**
「詰まった段に現れた定数 `nil` を変数に置き換える」という機械的手順で
候補を作った:
    app(revacc(t, a), cons(h, a)) = revacc(t, cons(h, a))

**この候補は偽である**(t:=nil で `app(a, cons(h,a))` ≠ `cons(h,a)`)。
駆動層はこれを**証明できなかった** — 偽の汎化を掴まされていない。

つまり素朴な「定数を全部変数に」は使えない。**どの出現を一般化するかの
選択**が要る(古典的に知られた難所)。健全性は保たれた。

## T' から T が出なかった
`app(?x, nil) → ?x`(app の右単位元)を足しても閉じなかった。
これは補題の連鎖の問題で、T' 自体の証明とは別。未追跡。

## 道筋の現在地
    汎化(手で与える)   ✅ T' を証明・Lean VERIFIED
    二段階正規化       ✅ 必要と判明し、実装(探索ではない)
    汎化(自動)         ❌ 素朴な定数一般化は**偽の候補**を作る。
                        選択の機構が要る。**ただし偽を証明はしない**
