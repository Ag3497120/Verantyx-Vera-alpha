# 事前登録: 汎化 — 命題を強めないと帰納が通らない場合

日付: 2026-08-19 / 実測前に登録

## 汎化とは
帰納法が通らないとき、**命題をより強い形に置き換える**と通ることがある。
帰納法の仮定が弱すぎるのが原因で、強い命題の方が強い仮定を与えるため。

古典的な例は累積引数(accumulator)を持つ関数である:
    rev(nil) = nil                    revacc(nil, a) = a
    rev(cons(h,t)) = app(rev(t), cons(h,nil))
                                      revacc(cons(h,t), a) = revacc(t, cons(h,a))

    目標 T: rev(l) = revacc(l, nil)
    → l についての帰納は**通らない**。段で `revacc(t, cons(h,nil))` が出るが、
      仮定は `revacc(t, nil)` の形しか与えない。
    汎化 T': app(rev(l), a) = revacc(l, a)
    → こちらは通る。T は T' の a := nil の特別な場合。

## 測るもの
1. **T が本当に通らないか**(駆動層が正直に詰まるか、空虚に通らないか)
2. **T' が通るか**(汎化した形なら帰納が回るか)
3. **T' から T が出るか**(a := nil を代入して直接に落ちるか)
4. **汎化を自動でできるか** — 詰まった段に現れた項
   (`revacc(t, cons(h,nil))`)から、定数 `nil` を変数に置き換えて
   T' を作る、という機械的な手順で届くか

## 検査
主張した各命題を Lean で独立に検査する(List を使い、rev/revacc は
Lean 側の定義で書く)。

## 判定(事前)
- **健全性**: 証明したと主張したものが Lean で偽なら失格
- **番犬**: 各段で偽の等式が証明できないこと(experiments/vacuity)
- 1〜3 は測定値。4 が届けば「汎化も自動化できる」、届かなければ
  **何が足りないか**を具体的に名指しする
