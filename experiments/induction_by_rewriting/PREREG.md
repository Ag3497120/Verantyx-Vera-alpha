# 事前登録: 帰納法は書き換えで実行できるか

日付: 2026-08-19 / 実測前に登録

## この実験を立てた理由(正直に)
前実験(induction_wall)で私はこう書いた —
「カーネルは項を書き換える。証明は目標を操作する。帰納法は部分目標に
割る規則で、カーネルには目標という概念が無い。規則を増やしても
越えられない。」

**これは測定ではなく私の推論だった。** 操作者の指摘を受けて見直すと、
前提が二つとも怪しい:

1. **目標も項である。** カーネルの項言語は任意の関数記号を許す
   (`op ∈ {+,-,*} ∪ 関数名`)。`eq(a,b)` も `and(p,q)` も書ける。
2. **帰納法の仮定は規則として足せる。** 段の場合分けで
   「`add(0,k) → k` を仮定してよい」というのは、まさに規則の追加である。
   カーネルは格納された規則を適用する装置なので、**仮定を規則として
   置けば、段の証明は純粋な書き換えになる**。

つまり帰納法は「カーネルに無い別の推論規則」ではなく、
**薄い駆動層(基底と段に割り、段では仮定を規則に加える)+ 既存の書き換え**
で実行できる可能性がある。向き付けを外側の層で実装したのと同じ形。

## 方法
自然数を `0` と `s(x)` で表し、加法を再帰的定義で与える:
    add(?x, 0)    → ?x
    add(?x, s(?y)) → s(add(?x, ?y))

これは**第二引数についての再帰**なので、次の3つは帰納法を要する:
    T1  add(0, x) = x
    T2  add(s(x), y) = s(add(x, y))
    T3  add(x, y) = add(y, x)          (可換律 — T1,T2 を使う)

駆動層の手順(閉じた規則、探索なし):
    基底: 変数を 0 に置換し、両辺を正規形にして一致を見る
    段:   変数を新しい定数 k に置換し、**帰納法の仮定を規則として加え**、
          変数を s(k) にした両辺を正規形にして一致を見る
    両方一致すれば「証明した」とする

## 検査(独立)
証明したと主張した各命題を Lean に出す:
    `theorem (m n : Nat) : ... := by induction ... <;> simp [...] <;> omega`
Lean が VERIFIED を返すかで、主張の真偽を独立に確かめる。

## 判定(事前)
- **T1 が通れば、前実験の「越えられない」は誤りだったことになる。**
  その場合は前の記述を訂正する。
- **健全性**: 「証明した」と主張したものが Lean で偽なら**失格** —
  駆動層が不健全ということなので、そこで止めて機序を分解する。
- T1/T2/T3 それぞれについて、通ったか・どこで詰まったかを記録する。
- 通らなかった場合も、**何が足りないか**を具体的に名指しする
  (「目標が無い」のような抽象的な理由では終わらせない)。
