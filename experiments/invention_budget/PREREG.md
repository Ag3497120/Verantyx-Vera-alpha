# 事前登録: 発明の予算門 — 反例の記憶と、型付きの打ち切り

日付: 2026-08-20。**この文書を書き終えてから測定を走らせる。**

## 無駄の形(推測ではなく実測してから設計した)

確認14が4時間かかり、発明の門が **1,325,982候補**を反駁した。
その形を M1(min の可換律・拒否で終わる目標)で計測:

    13.6秒 / 接地検査 1,381回 / **相異なるのは358件だけ = 重複74%**
    最多: 「min(a,b) = min(b,a)」を7回、「min(a,b) = 0」を6回…
    結果の内訳: REFUTED 1,368 / PASSED 13、昇格した補題 **0本**

つまり主な無駄は「探索が広い」ことではなく、**同じ反例を何度も引き直して
いる**こと。接地検査は決定論的な純関数(店にも時間にも依存しない)なので、
記憶すれば消える — 新しい賢さは要らない。

## 変更(2つ、どちらも既存の型のまま)

1. **反例の記憶**: (lhs, rhs) → ground_check の結果を run 内で記憶。
   同じ等式は二度検査しない。**判定は一切変えない**(純関数の記憶なので
   結果は同一 — 速さだけが変わる)。
2. **型付きの打ち切り**: 1目標あたりの接地検査回数に上限(既定 4,000)。
   超えたら `REFUSED` の理由を `invention_budget_exhausted` にし、
   使った予算を報告する。**黙って止まらない**(UNKNOWN_BUDGET と同じ族)。

## 採択基準(完了基準5点)

- N1 正: 判定が**一切変わらない** — 確認13の全48目標(証明41・反駁7)
  で verdict が完全一致
- N2 反証: 偽の目標が引き続き反例つきで REFUTED(反例も同一)
- N3 拒否: 予算を使い切った目標は型付きで名乗り、その事実が台帳に
  残る(黙って諦めない)。予算上限を小さくした対照走で発火を確認
- N4 順序: 規則列反転でも verdict 一致(記憶は順序に依存しない)
- N5 独立: 補題監査(拡大接地・Lean)が全通のまま
- 速さは**報告のみ**(採否に使わない): 確認13の所要時間の前後

## 停止条件

N1違反(判定が変わった)→ 記憶が純関数でない箇所がある = 器の欠陥。
即棚上げして機序究明(この場合、接地検査が隠れた状態に依存している
ことになり、それ自体が重大な発見)。
