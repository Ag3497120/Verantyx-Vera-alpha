# 事前登録: 分岐のある書き換えで、構造は正規形に至れるか

日付: 2026-08-19 / 実測前に登録 / 前実験(structure_to_lean)の続き

## 前回との違い
桁上がり加算は規則の適用順に**分岐が無かった**(202規則が排他的)。
今回は8規則の代数(add_zero/mul_one/mul_zero/sub_zero/sub_self)で、
**一つの項に複数の規則が同時に適用可能**な式を対象にする。
カーネルは leftmost-innermost・最初に発火・**後戻り無し**なので、
選び方を誤れば正規形に至れない可能性がある。合流性は保証されていない。

## 測るもの
無作為生成した線形整数式(変数 a,b,c と定数 0,1、演算 +,-,*定数)200本:
  ① `simplify` の verdict: ANSWER(正規形到達)/ UNKNOWN_BUDGET(予算切れ)
  ② ①の結論を Lean が独立に検査: `theorem (a b c : Int) : 原式 = 簡約 := by omega`
     — omega は線形整数の完全手続きで、偽は落ちることを実測済み
  ③ 簡約の**縮み具合**(元の項サイズ / 簡約後のサイズ)

## 判定(事前)
- **健全性**: ①が ANSWER を出した全件で、②が VERIFIED。
  1件でも UNPROVEN が出れば、書き換えが不健全ということなので**失格**。
- **完全性**: ANSWER 率を記録する(何%が正規形に至るか)。
  これは合否ではなく**測定値**。低くても失格ではない — 後戻り無しの
  代償がどれだけかを知るための数字。
- 予算切れが出た場合、その式を記録する(どんな形で詰まるかが次の設計の入力)。

健全性が崩れた場合は、そこで止めて機序を分解する。
