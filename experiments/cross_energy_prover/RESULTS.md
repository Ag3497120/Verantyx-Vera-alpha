# 実測結果: 立体十字エネルギー証明器 — 梯子の発明が初めて動いた

日付: 2026-08-20。構想の出所は「これまで.pdf」(端のクエリでエネルギー
比率が変わり中心への経路が変わる、という立体十字の原構想)。事前登録は

## 何を作ったか(新しい器官3つ + 写像1つ)

1. **有限接地モデル検査**(ground_check) — 候補等式を小さい接地項で全数
   評価し、食い違えば REFUTED(反例つき)。「証明できない」と「偽」を
   この系で初めて分けた。
2. **候補の発明** — 詰まった段の部分項を抽象化して補題の左辺を作り、
   右辺は同じ変数上の小項を列挙し、接地検査で淘汰(向き: サイズ非増大、
   右辺変数⊆左辺変数)。
3. **十字のアジェンダ** — 生き残った候補を ShellCross の腕に置き(面=
   由来・接地数・右辺・エネルギー)、axis_energy と同じ形のエネルギー
   (接地質量×(1+被覆+特定性)−試行台帳減点)が試行順を決める。
   **エネルギーは順序だけを決め、真偽には触れない — 票を持たない。**
4. 帰納駆動・AC正規化・向き付け・Lean 証人は探索実験(2026-08-19)の
   実測済みの形をそのまま流用。

## 未達と正直な注記

- **C1 rev(app(x,y)) = app(rev(y),rev(x)) は2回の事前登録とも未達。**
  診断: 必要な一般結合律 app(app(?x,?y),?z)→app(?x,app(?y,?z)) は
  3箇所の同時抽象が要るが、抽象化の同時上限(3個・走査順)が先に
  尽きる。PREREG2 の停止条件どおりここで打ち切り。次は抽象化の形の
  再設計(極大異質部分項の同時抽象)を、新しい事前登録で。
- **R3/R4/R8(可換・結合)は ac_norm が前提として持つ** — 帰納で
  証明したのではなく、比較の正規化に焼き込まれている(run_ac.py 由来の
  設計)。Lean が真であることは検査済みだが、「導出した」とは言わない。
- **エネルギーの寄与はこの規模では見えない**(無効化対照と証明数・
  ノード数ほぼ同一)。候補が数個しか生き残らない小さな詰まりでは
  順序が効かない。効くとしたら候補が溢れる領域 — 未測定。
- 発明された補題には冗長なもの(C4 の L11〜L17)が混ざる。全て真で
  Lean 検査済みだが、最小の梯子ではない。
