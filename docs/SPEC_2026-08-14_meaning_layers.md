# 仕様 — 意味理解の三層+照会演算 (2026-08-14 固定)

設計: Fable 5 / 実装・測定: grok 4.6 xhigh。この文書が契約であり、
実装者は本文から逸脱しない。逸脱が必要になったら実装を止めて報告する。

三層(型・関係・内容)+照会演算(構造差分)で意味理解の設計を一周
閉じる。納品は 3 単位に分け、順に検収する:

    納品1  述語プロファイル抽出   共通部品・機械オラクル付き
    納品2  構造差分演算子         防御線2本込み
    納品3  投入時整合検査         気泡原則の意味版・独立納品

## 共通規律(全納品に適用)

- 生成なし・LLM 呼び出しなし。全て決定論。
- プロファイルは手渡し側の産物。**票(census)には決して混ぜない**。
  サイドカー JSON として保存する。
- 同点は棄権。閾値未満は型付きで棄権。沈黙は必ず型を持つ。
- git commit は実装者はしない(検収後に設計者が行う)。

## 納品1 — 述語プロファイル抽出

### 目的
主題ごとに「どの述語と共起するか」の分布を持つ。差分演算(納品2)と
型層測定の共通土台。

### 実装
- `verantyx/predicate_profile.py`
  - `extract(pages) -> {subject: {predicate: count}}`
  - 入力は `tools/build_shallow_shelf.pages()` (jawiki リード文)。
  - 述語抽出は決定論。形態素解析器が環境にあれば使ってよいが、
    無ければ決定論ヒューリスティクス(動詞語尾・「〜である」型の
    述部フレーム)で可。**どちらを使ったかを出力 JSON に記録する。**
  - 保存: `~/Projects/vera-corpus/build/predicate_profiles.json`
    形式: `{subject: {"predicates": {pred: n}, "total": N}}`
    生カウントを保存する(正規化は読み手が行う — 納品2の防御線2)。

### 測定 (`tools/measure_predicate_profile.py`)
機械オラクル: held-out 予測。
1. 述語 3 件以上の主題を対象に、(主題, 述語) 対の 20% を held-out。
2. 残りから、格子 kin(共有単位の族)の平均プロファイルで
   held-out 述語を予測。hit@5 / hit@10。
3. ベースライン: 全域頻度上位(型情報なし)。
4. 報告: 被覆(述語3件以上の主題数/全主題数)、hit率の対比、
   kin が引けず棄権した数。
kin 予測がベースラインに勝てば「プロファイルは型構造を捉えている」が
数字になる。負ければその数字も docstring に残す(隠さない)。

## 納品2 — 構造差分演算子

### 目的
「A と B の違いは」に、構造署名の差分で答える。

### 防御線1 — 不在と否定を混ぜない(最重要)
「A固有」の定義は「A に実測あり・B に実測なし」。
**否定文の生成を型レベルで禁止する**: 出力スキーマに否定スロットを
置かない。出力語彙は「実測あり」「実測なし」のみ。
「B は〜でない」という文字列を組み立てるコードパスが存在しないこと。

### 防御線2 — 被覆の非対称
(a) 述語プロファイルは比率に正規化して比較する(絶対数を使わない)。
(b) 片側の面数・述語数が閾値(既定: 3)未満なら
    `INSUFFICIENT_PROFILE` で棄権する。
(c) 出力に両側の被覆数(面数・述語数)を必ず併記する。
差分の信頼度は薄い側が決める。

### 実装
- `verantyx/structural_diff.py`
  - `diff(store, a, b, *, profiles, lattice, shelf) -> Dict`
  - 局所計算: 各主題の k 近傍のみ(全ソブリン走査をしない)。
  - 比較層: ①型(述語族) ②述語プロファイル(正規化) ③格子 kin 族
    ④面の質量配分 ⑤辺の向き(作用する側/される側) ⑥棚定義文。
  - 出力: 共有 / A固有 / B固有 の三束。各項目に出所(どの層・どの
    辺)を付ける。同点は棄権。

### 測定 (`tools/measure_structural_diff.py`)
二段:
1. 機械オラクル: 差分が「A固有」と主張した述語が、held-out 文で
   実際に A 側にのみ現れる率。
2. 事前登録の目視軸: 差分質問 30 問のバンクと「期待される主軸」
   (例: りんご/電気 → 食用 vs 流動)を**実行前に**バンクファイルに
   登録してから走らせる。出力がその軸を上位 3 束内に出すかを採点。
   登録前に出力を見ることを禁ずる。

## 納品3 — 投入時整合検査

### 目的
新概念の構造プロファイルが族の模様と矛盾する取り込み
(伝導するりんご)を、投入時に異常として検出する。
気泡原則(見えない取り込みを許さない)の意味版。

### 実装
- `verantyx/ingest_coherence.py`
  - 新規主題の述語プロファイルを、その格子 kin 族の平均と比較。
  - 逸脱が閾値超なら `COHERENCE_ANOMALY` を**警告として**記録する
    (取り込みは止めない — 検閲ではなく台帳)。
- 測定: 既知コーパスに人工の異常文を混入させ、検出率と偽陽性率。

## 検収基準

各納品は (1) fork 相当の回帰が全通過 (2) 測定数値が docstring に
焼き付き (3) 設計者レビューで防御線の遵守確認 — の三点で検収。
